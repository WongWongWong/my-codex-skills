# 植物验收清单

按任务选择必要检查。只读审计不能声称完成运行验证；新资产按需求验收，已有资产改造与基线比较。仅因修改一个名称或独立属性，不扩展为整库性能测试。

## 制作或改造前

- 目标场景、目标资产与编辑范围已明确，已有改动可辨认。
- 记录需要保留或新建的轮廓、材质、动作、真实伸缩与特效，以及实际使用尺度。
- 识别根结构、标签、动画入口、关节/挂点引用、交互与查询契约。
- 按制作规范的口径记录结构、几何和特效指标；区分推荐预算与项目已确认预算。
- 规划可合并单元；只把运动、变形和独立外观控制兼容的几何列为候选。
- 性能任务明确目标设备、画质、镜头和数量。未知条件如实列出，不捏造基线。

## 静态结构验收

- 根实例、实际缩放范围、Model（包括 Tool 等子类）的 PrimaryPart、枢轴、名称、标签和脚本引用符合项目约定。
- 没有无用途的重复连接、失效端点或无跟随关系的附属视觉件。
- 锚定、Massless、碰撞、触碰和查询按运行上下文配置。
- 骨架统计和中性数据与改造后的实际结构一致，变形归属能正确解析。
- 特效挂点仍在正确的运动单元中；体积发射所依赖的几何被保留。
- 关联的已有远景资产和源模型统计没有失配。
- 交付对象不包含未获要求的制作辅助层、备份或测试副本。

## 完整表现验收

对有对应表现的资产检查：

- 正面、侧面、背面和正常游戏视距下的轮廓、颜色、材质与遮挡。
- 中性姿态、最大弯曲、最大拉伸、眨眼、变色及动作切换。
- 挂点、粒子、Trail/Beam、灯光在完整动作中的位置、方向与跟随。
- 最小、正常、最大使用尺度，原有生长过程及缩放后的接地位置。
- 无散落、拉裂、跳变、错误拉伸、异常碰撞或效果丢失。
- 用户明确批准的表现变化按新目标检查，不能反过来以保留旧效果为由拒绝需求。

## 性能验证

计划阶段只制定测试方案。用户已授权执行优化或制作时，范围内必要、可恢复的动态验证随执行开展，无需重复索取授权；超出约定资产、环境或副作用范围的测试另行确认。先记录原始资产；控制镜头、画质、尺寸序列、更新频率和并发数量。分别记录冷启动与预热条件，避免将首次资源加载差异算作优化收益。

### 单株定位

按当前疑点选择实验，不强制为每个任务跑所有组合：

1. 隔离业务与额外驱动后，测完整模型的纯缩放。
2. 在临时测试副本中移除待排查的粒子发射器等组件，保持相同缩放序列，比较其增量。
3. 比较骨架/局部变形开启与关闭时的直接耗时和后续帧。
4. 对模型版本做完整表现对照，确认减件、减面或消除重复更新的实际效果。

“关闭发射”与“移除发射器”是不同实验：关闭发射不一定排除 ScaleTo 修改其属性的成本。粒子、骨架及渲染可能相互影响，各对照差值不能直接相加成百分比。

隔离修改只用于测试副本。暂停动画或移除效果的结果不能充当完整资产最终验收，也不自动成为交付方案。

### 指标与批量测试

记录需要的指标，不只看平均 FPS：

| 指标 | 用途 |
|---|---|
| Clone、初始化、挂入场景的耗时 | 区分创建尖峰与持续更新 |
| ScaleTo 实际调用次数及直接耗时 | 判断调用本身与采样条件 |
| 整帧 P95、最大帧耗时和超预算帧数 | 衡量卡顿与稳定性 |
| 后续帧的脚本、物理、渲染/GPU 工作 | 避免漏掉调用返回后的引擎成本 |
| 稳定状态耗时 | 检查优化是否引入持续退化 |
| 视觉完成时间 | 防止通过延迟表现伪装性能改善 |

- 单株问题先在单株条件复现；再使用项目实际并发数量测试，不硬编码某个旧项目的容量。
- 采样次数足以区分明显波动与一致趋势；说明时长和重复条件，不以一次偶然快帧宣称收益。
- MicroProfiler 的父子作用域耗时不要重复相加，多线程工作量不要当作关键路径帧耗时；需要时读取当前工具提供的性能分析说明。
- 若动态测试因工具、设备或场景条件不足无法完成，明确报告“未验证”，不要写“性能通过”。
- 不预先承诺固定 FPS 或提升比例。项目门槛确定后按该门槛验收；缺少门槛时报告实测变化和限制。
- 验证结束只清理由本次测试创建的对象或文件，恢复本次改变的临时场景状态，不影响用户原有资产。

## 集成与交付记录

资产独立视觉/缩放测试与游戏接入测试分开。任务包含游戏接入时，再核对实际使用场景中的农场摆放、手持、孵化、拾取、查询和声音；不把未接入的项目功能搬进美术场景。

每次交付用简短记录说明：

- 目标资产、批准的范围、实际修改的实例/文件与变更原因。
- 改造前后结构指标及统计口径。
- 确认保留或批准改变的表现，动作与尺度检查结果。
- 性能测试环境、对照条件、测量结果与未验证项。
- 关联元数据、挂点、已有 LOD 和集成检查结果。
- 预算例外及其依据；范围外发现只报告。

新资产交付同样需要结构和表现结果；没有旧版本时以确认需求和明确的对照场景为基准，不虚构“优化前”数据。
