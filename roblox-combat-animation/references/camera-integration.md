# 招式镜头接入

适用于已要求或已确认采用的招式镜头。只修改其他表现时不自动新增运镜。预览开关默认关闭，不意味着正式迁移可以省略已确认的镜头。

## 职责与配置

| 内容 | 负责人 |
|---|---|
| 起势推近、分段取景、终击震动、结束回镜的节拍与幅度 | 招式可编辑配置 |
| 根据当前动作进度计算镜头表现，管理本轮状态 | 项目适合复用的招式模块 |
| 基础机位、屏幕和体型适配、HUD 避让、最终相机写入 | 场景现有相机系统 |
| 演示站位、独立机位、预览开关 | 预览控制 |

招式模块提供表现数据，由调用方应用到现有相机循环，不另起循环争抢控制。预览和正式战斗共用招式节拍计算，各自保留场景适配。沿用项目结构，不要求所有项目采用 `FightActionHelper` 这个名称。

迁移前对照起势、连击、终击、回镜逐段检查，整合已有推镜与震动，避免重复叠加。镜头参数与动作资源关联，不依赖预览脚本中的固定坐标或重复节拍表。

## 时间与状态

优先以当前动画进度（例如 `TimePosition`）、速度和播放状态驱动表现，避免另维护与动画脱节的计时器。加速、重新播放和换招后仍按当前轨道取值。

正常结束时回到战斗基础机位并清除本轮偏移；检查结束标记和连续换招交界，避免残留上一帧。被替换、中断、超时、退出或角色死亡时，按现有生命周期解除本轮影响，不让旧回调覆盖新镜头。

致死与 KO 按业务顺序衔接。若项目约定奥义中途致死仍播完整套，则镜头同步完成后再交给倒地镜头；不要提前恢复或跨状态硬切。最终归还状态和过程的平滑程度都需要检查。

## 场景适配

保留现有屏幕比例、Boss 体型、基础机位与 HUD 避让。不能直接套预览固定距离；起势近景也应保证关键角色部位和接触点可见。

检查安全画幅限制是否削弱到几乎看不出推拉。应在可读性与镜头力度间调整配置，不为强行推近而裁掉关键动作。手机横屏、窄画幅和大体型目标需要实际画面证据。

## 预览与验证

预览开关默认关闭，关闭时不接管相机或执行招式镜头更新。途中关闭、停止或销毁预览脚本时释放控制并恢复接管前状态；验证实际销毁路径。

《格斗之王》终极技预览区分基础起势与镜头演出：起势聚气、亮核等统一发动 VFX 及启动提示音在普通预览中仍播放，声音遵循音效开关；暗转、轮廓等演出效果随镜头预览开关启用。不能因默认关闭镜头而禁用全部起势。途中关闭镜头时解除本轮暗转与轮廓、恢复相机及受影响的画面状态，不误停仍在播放的动作与基础起势；停止、中断、重播或实际删除预览脚本时，按所属生命周期清理旧轮影响，不能破坏新轮或场景原有状态。这个预览约定不意味着正式播放依赖预览开关。

覆盖完整播放、加速、连续出招、动作替换／中断、致死到 KO、超时与主动退出。观察相机争抢、突跳、裁切、残留偏移和进出镜头扫空场。改变共用镜头逻辑后回归实际受影响的旧招。

测试前确认场地高度、地面和实际站位；测试副本被地面遮挡不能误判为镜头算法问题。正式战斗测试的奖励／存档隔离遵循 [预览与验收](preview-and-acceptance.md)。
