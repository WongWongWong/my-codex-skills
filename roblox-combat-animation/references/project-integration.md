# 项目适配与正式迁移

## 制作前核对

先只读查看实际调用链、资产与配置。记录对本次设计有影响的事实：

- 基础连击在训练、战斗中如何触发；奥义如何起播、结束、变速和中断。
- 当前标记名称、大小写、参数和命中回调契约；不要凭示例发明一套新协议。
- 受击是逐击短片段还是整段配对，目标已有动画如何交接，换目标、死亡和退出时如何停止。
- 致命受击、QTE、胜利倒地由谁决定，落地特效、声音、完成通知在哪触发。
- 时长、命中数量、恢复点是否参与伤害、冷却或业务等待。修改时记录前后变化和影响，不顺带更改数值。
- 音效开关、混音分组、预加载与回收入口，以及训练、战斗需要的资源形态和动画引用。
- 招式镜头与场景基础机位的分工、现有起势推镜、屏幕和体型适配；按动作名查找的起势、首击时间等配套配置。
- 制作《格斗之王》终极技时，核对统一发动 VFX、启动提示音和现有播放入口，分别列出公共起势与角色专属蓄力，不能只检查主动作或手部元素效果。

优先复用已支持能力。需要扩展时明确缺口、最小改动和兼容方式；不要先做只能演示的流程，再假定能直接接入。读不到实现的部分标为待核实。

读取当前配置与工作区改动，保留用户已有修改。聊天中的“尚未接装备”等历史状态不能替代当前事实，也不能据旧快照覆盖用户新配置。

## 受击与致命

普通受击按命中方向和力度反馈，并能继续承接下一击。配对动作仅在抓持等确有需要且项目支持时使用，明确双方同步和中断处理。

**《格斗之王》当前项目的明确约束：** 基础连击与奥义的最后一击受击动画必须保持站立，不包含倒地、击飞或起身；普通受击默认站立。未致命时恢复继续战斗，致命时由现有业务入口在规定时机执行唯一一次倒地，并保证姿态连续。该要求适用于本项目后续新招式。只有用户明确要求新增倒地／击飞玩法时才扩展相应业务支持，不能仅因参考存在倒地就自行加入。

致命处理服从实际业务：核实基础连击是否在本击恢复点倒地、奥义是否完成剩余攻击、QTE 如何接入。不能把某个项目的策略推广为固定规则。

在其他项目或明确获准扩展的玩法中，如招式含倒地或击飞，必须指定最终姿态和业务倒地的衔接负责人。避免先躺倒、瞬间站起、再播胜利倒地。落地声、落地 VFX 和完成通知应各触发一次。

## 版本对比与训练目标

用户要求保留原版时，复制独立版本并分别配置动作源、演示目标、音效和必要的专属受击资源；先检查共享引用，需要改动的共享资源应隔离，避免旧版一起变化。可安全共用的模块和未改资源继续复用，不能因为制作 V2 就默认修改共用 helper。新旧版并排预览供比较，不自动覆盖或迁移正式资源。

基础连击用于训练时，核对有陪练、无陪练、切换陪练的实际行为。挥击属于出招本身；受击动作、命中特效与命中声应由项目确认的实际命中驱动，不能在无目标时伪造命中，也不能让已取消的旧目标回调作用到新目标。

## 资源存放与运行时归属

验收资产可集中存放于独立目录，无需复制正式目录布局。运行时挂点、局部偏移、目标映射、触发与清理方式应可复用。

演示站位、循环控制、模拟致命开关、展示地面、预览镜头开关和独立演示机位是预览设施。业务资产、播放逻辑不能依赖这些固定坐标或测试开关。已确认的分段运镜、终击震动和回镜属于招式表现，应随招式迁移，不能因为它最初写在预览脚本里就遗漏。具体分工见 [镜头接入](camera-integration.md)。

## 动画发布方式

动画已在 Studio 中时，优先核对并使用能直接发布实例的接口；仅在直接方式不适用时考虑导出上传或界面操作。不要未经接口调查就占用用户鼠标和窗口；确需电脑操作时先说明原因、操作及影响。

`AssetService:CreateAssetAsync()` 是直接创建 Animation 资产的候选。使用前核对当前官方资料、工具能力和执行环境，不仅凭工具列表没有专用名称或一处文档未列支持类型就认定不可用。区分“接口支持”“当前环境与权限允许调用”“发布成功”“当前游戏实际可播放”。在已授权的发布范围内验证，不为探测能力擅自发布无关资产。

核对体验所属个人／群组及资产归属，记录返回结果和持久 ID，回填后验证实际加载。不能使用预览临时注册 ID 作为正式交付；某次 MCP 调用成功也不能保证其他环境必然可用。

官方依据：[Animation 支持公告](https://devforum.roblox.com/t/asset-import-and-management-recap-jan-apr-2025/3642901)、[AssetService API](https://create.roblox.com/docs/reference/engine/classes/AssetService#CreateAssetAsync)。

## 迁移阶段

| 本轮目标 | 对应完成标准 |
|---|---|
| 验收副本 | 独立预览与适用的模拟分支通过 |
| 正式资源迁移 | 持久资源和正式模块可调用，不依赖验收目录；可在临时角色上测试，不要求顺带接装备 |
| 装备／玩法接入 | 配置引用完成，从实际训练、战斗入口验证 |
| 线上发布 | 按已授权范围发布并检查游戏版本 |

只迁移正式资源可以独立完成；未授权时不修改装备、获取方式、伤害倍率，不自动装备或发布游戏版本。实际业务验证的副作用隔离见 [预览与验收](preview-and-acceptance.md)。

## 正式迁移

在用户要求接入的范围内执行：

1. 记录验收资产到正式资产的映射和当前基线，保留可编辑源。专属受击、特效和音效使用独立名称，避免覆盖其他招式共用资源。
2. 按实际需要发布动画资源并替换引用，核实当前体验能加载使用。
3. 迁移动作、受击、VFX、音效、已确认的招式镜头及配置；确保挂点、渐隐和尾部回收逻辑一起迁移。核对起势、首击时间、按动作名查找的资源和映射，不能只复制主动作。《格斗之王》终极技须逐项核对统一起势预制、启动提示音、触发配置、资源映射及暗转／轮廓等已确认演出效果的应用与恢复逻辑；复用已有正式资源时核实引用与调用，不必重复复制，也不能让起势只在待验收预览中成立。
4. 按授权阶段及项目真实配置来源更新引用，避免只改生成文件造成下一次生成覆盖。检查正式播放不再依赖验收目录、预览脚本或临时动画注册。
5. 修改共用模块时保留既有招式行为，除新招外回归实际受影响的旧招，检查命中、声音、镜头和收尾；独立资源命名不能代替模块回归。
6. 按阶段选择测试入口：资源迁移调用正式模块和资源；玩法接入从实际训练、战斗入口测试同步、致命、打断和退出。资源测试不能冒充玩法已接入。
7. 交代动画发布、正式资源迁移、装备／玩法接入及线上发布各自状态，报告遗漏，不笼统宣称全部完成。

对照已确认的表现清单逐项记录迁移去向，尤其检查可能只存在于预览脚本中的声音、分段镜头和收尾逻辑。主动画、部分起势或音效已迁移，不代表完整招式迁移完成；缺项应按本轮授权补齐，超出范围则明确列出，不能隐去。

单纯制作验收副本不自动包含正式接入、数值调整或线上发布。
