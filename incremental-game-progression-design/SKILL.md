# 增量模拟器成长设计

以玩家的下一次选择为起点。对每个阶段，先写清玩家想获得什么、为什么值得投入、获得后能做什么，再决定用哪些数值支撑这段体验。

## 还原成长循环

从新玩家的实际起点走一遍：做什么动作，得到什么资源，资源花在哪里，花完后哪个环节发生变化。已有项目要核对配置和实际读取它的逻辑；新项目把未确定的机制列为假设。区分用户要求、已确认的机制、设计建议和模拟假设。

辨认升级影响的是单次产量、行动频率、成功率、容量、自动化程度，还是能进入的内容。核实加成怎样叠加、买下后何时生效，以及资源何时结算。按项目实际情况纳入离线收益、多货币、重置、随机掉落或付费加速。参考同类游戏时，比较可观察的选择和重复操作，对推算的时长注明依据。

## 安排阶段目标与内容密度

从第一次有效操作、第一次购买、第一次明显提速，到玩家需要改变策略和完成长期目标，选出适合该游戏的里程碑。写明计时起点，区分主动操作时间、在线放置时间和现实经过时间。

给每个阶段写下三件事：

- 玩家眼前买得起什么，买完能立即感受到什么？
- 有什么值得多攒一会儿？立即购买与继续储蓄各有什么收益？
- 达成目标以后，哪一项新选择变得可行？新获得的能力有多长时间可以发挥作用？

把内容安排到这些选择出现的时刻。早期用短循环让玩家看懂投入与回报；中期让不同投资方向在不同条件下值得选；后期给高阶能力留出使用空间。如果某段时长只能靠重复同一动作或延长等待来填补，指出具体区段和取舍。

## 联动设计收益、价格与解锁

把产出、消耗、升级效果、售价和解锁条件放在同一条时间线上。先找到限制玩家进度的环节，再判断哪项投资能解除限制。例如，容量经常装满时，扩容能增加实际收获；容量一直有余量时，相同的扩容对当前目标可能毫无帮助。

优先让有经济回报的升级形成购买关系：买下 A 后，玩家即使付出了一笔资源，也有机会比直接储蓄更早得到 B。A 和 B 可以属于不同系统。允许数值跨数量级增长，但要检查购买前后的实际体验、相邻档位的价值，以及高阶回报会不会让前面的投资失去意义。保留已有数值时，指出它满足的目标。

对有指定购买顺序的新手流程，逐步结算余额：获得资源、扣除售价，再把余额带到下一步。复刷、重复生产和一次性奖励按各自的实际规则计算。

## 从同一状态验证一笔投资

选一个玩家接下来确实想得到的目标 B，从相同的余额、库存、已有升级、解锁进度和操作习惯出发，比较两条路线：

1. 直接积攒到足以获得 B。
2. 先支付 A 的完整成本，再利用 A 提供的能力获得 B。

**净节省时间 = 直接获得 B 的时间 − 先买 A 再获得 B 的时间。** 正值表示这笔投资在该条件下能让 B 更早到手。

两条路线都可使用当时实际开放的途径，包括购买 A 后才有机会进入的高收益内容。计入整次生产或行动、领取周期、切换与操作耗时。检查余额刚好够买、还差一个周期等边界；平均产出率可能掩盖多做一次行动的代价。

如果结论随在线时长、操作频率或购买顺序改变，就标明适用条件。自动化可以用减少了多少次操作来判断，收集品可以用完成收集目标来判断，最后一项升级则看它对终局目标的贡献。

## 用不同玩法复核整条路线

按游戏实际支持的选择，对照典型路线和至少一条合理替代路线，例如主动操作与放置、频繁再投资与跨档储蓄、专攻一项与分散投资。商店允许跳档，推演也允许跳档。只模拟了有限路线时，说明结论的覆盖范围。

| 复核项 | 需要回答的问题 |
|---|---|
| 里程碑时长 | 各路线何时达成目标？差异来自哪些选择或假设？ |
| 最长成长空档 | 哪两次有意义的购买、解锁或策略变化之间隔得最久？期间玩家在做什么？ |
| 重复成本 | 为一次升级要重复多少次同样的操作，或等待多少个相同周期？ |
| 档位价值 | 哪些档位自然会买，哪些经常被跳过？是价格、收益，还是出现时机造成的？ |
| 能力使用期 | 玩家能用新能力完成哪些目标？多久之后它会被替代？ |

针对具体原因调整，再用相同起点复算。总时长达标而中段出现长空档时，优先检查内容是否集中在同一时刻，以及调整购买顺序或收益分布能否改善体验。

## 交付与实施

交付与请求相关的成长循环、阶段目标、关键数值、代表性购买对照和仍待验证的档位。说明数据来自项目配置、离线推演还是真人实测。对已有项目列出修改范围及理由；按当前项目的执行授权写入，并回读核对配置源和游戏实际使用的数据。
