# Roblox 游戏实测与分析

按用户授权的范围操作。先确认 Roblox Experience、当前窗口和测试条件。如果用户要求单人局，在开始采样前确认队列显示 `1/1`，进局后检查有无其他玩家。把任务成功定义为可观察状态，例如背包先增加再减少，且发电机进度发生对应变化。输入发送成功只说明脚本完成了输入。

1. **校准。** 先验证前台窗口、客户区尺寸、按键保持与释放、镜头转向、HUD 和实际交互。脚本采集坐标与 UI 工具截图坐标可能不同。换机器、宽高比、语言、缩放或镜头设置后重新核对关键区域。
2. **实时执行。** 用本地画面反馈处理短动作和连续输入，把对话留给选择目标与看结果。脚本先识别场景目标，再操作和验证结果。持续看见箭头只表示有导航提示。目标可能在墙后，角色也可能没有前进。掉血检测属于受击后的应急信号，提前避开僵尸需要独立的实测证据。
3. **验证并记录。** 保留单人局人数、关键状态、各阶段耗时、人工补发输入、失败表现及样本条件。地图分析优先同一局升级前后从相同位置和方向记录，再用新局判断哪些变化可重复。用「观察」「推断」「待验证」标记结论。

使用[校准和验收参考](references/windows-roblox-playtest.md)时，调用 `scripts/roblox-route-prototype.ps1` 检查环境，调用 `scripts/invoke-fuel-route.ps1` 复跑已校准的取油路线，或调用 `scripts/measure-replay.ps1` 在离线录像里复核视觉信号。取油示例针对 *Survive the Apocalypse*，其他游戏需要按画面和交互重新定义路线。

恢复实测后，如果新证据改变了操作方法、校准范围或结论，同步更新本 Skill 的对应规则、参考记录和实际复用的脚本。注明验证条件和是否需要重测。同步更新仍遵循会话和仓库的执行授权。
