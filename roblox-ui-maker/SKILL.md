# Roblox UI Maker

把参考、示意图、素材和实际 UI 对应起来。按当前任务阶段使用流程，不为小范围修改重新制作整套 UI。

## 任务阶段与边界

- “计划／讨论／审查”只读调查和输出方案，不生成文件、不修改 Studio。
- “先出示意图”授权制作约定的预览，不代表批准生产素材、脚本或预制体变更。用户要求先审图时，完成预览后等待反馈。
- “开始执行”按已经确认的范围推进。已有视觉方案和实施授权时，不重复请求批准；范围缺失且影响实现时才澄清。
- 分清已确认要求、实施建议和未核实部分；保留用户明确推迟的工作。美术制作不附带改变战斗、QTE、伤害、奖励或数据规则的权限；用户明确要求并授权的开战时序调整属于实施范围，无需重复请求同一权限。
- 实施前列明脚本、预制体路径和素材输出位置，检查现有改动与调用点。与 `wjf-coding` 同用时沿用其范围、代码风格和生命周期规范，不复制或另立一套规范。

## 核实参考与可实现性

1. 使用当前可用的工具实际查看用户提供的图片或视频。视频至少观察与需求有关的状态和转场；记录可核对的时间点或画面。封面、标题和文字摘要不构成“看过战斗 UI”的证据。
2. 分别记录观察到的布局、颜色、字形、层级和动态节奏，以及从这些观察提出的实现建议。无法访问的片段明确标注未核实，尝试可用的浏览器或连接器后再说明缺口。
3. 读取现有 UI 层级、字体、图片、状态来源和事件。确认素材导入、原生文字、裁切、Tween 等手段能覆盖目标；未验证的效果标为待验证，不承诺像素级还原。
4. 示意图与运行画面使用可比较的视口比例。对受游戏场景、头像或模型限制的部分单独标注，避免把背景美术差异算成 UI 布局差异。

## 示意图与资源拆分

- 明确玩家信息、Boss 信息、计时、连击、能量、口令、交互等实际需要的大区域。测量区域边界和宽高比，包含必要装饰留白；忽略不参与布局的零散飞白。
- 为每个区域说明：根容器、图片层、原生文字、交互命中区、动态属性。按钮可视图和点击范围应一起考虑。
- 区分固定装饰字、动态名称与数值，按用户确认的方向选择 PNG 或原生文字。选择图片口令后，实施时不得擅自改为字体近似；编辑器占位文字与运行时显示一起检查。
- 选定动态字体及备用方案前核查项目能否使用。不要把字体名称写进生成图就当作项目已经拥有该字体。
- 提供能映射到实际层级的示意图，并说明关键状态如何变化。用户已给出认可版本时复用，不重新发散视觉方向。
- 资源清单只列本次需要的素材、用途、画布比例、透明要求和目标实例。未授权额外文档时可直接在回复中列出，不新增清单文件。

## 素材制作与导入

- 使用环境中可用的图像生成／编辑工具，遵守其技能和引用图片要求。生成前检查已有素材，按认可的方向制作；不通过大量无目标的重生成代替定位问题。
- 独立生成需要分别运动、着色或裁切的层。动态名字、数值不要烘焙进装饰图；背景、文字、槽口等不能分离时先修正资源拆分。
- 检查真实 Alpha、画布尺寸、有效图形边界、透明留白和边缘质量。透明槽口必须真正透明，黑色或棋盘格图案不是透明。
- 保存到用户约定的位置，交付使用绝对路径。先从已指定路径和项目既有资产目录确定位置；只有多个位置无法判断且影响交付时才澄清。未指定保存位置的首张预览可先使用工具返回的产物位置。区分交付目录与工具自行管理的缓存；没有设置能力和验证结果，不声称所有临时文件已迁移，也不擅自修改 Codex 全局配置。
- 上传后保留文件与资源 ID 的对应关系，验证目标体验中实际加载及显示。上传成功不等于材质可用；失败时按返回原因处理，重复失败且没有新依据时停止盲目重试并报告缺口。
- 如果选用透明开口面板覆盖矩形进度条，读取 [PNG 遮挡面板与分层进度条](references/png-mask-bars.md)。其他 UI 不必加载该参考。

## Studio 预制体与比例

- 固定结构与基础样式保存在可编辑预制体；脚本负责数据和动画，复用项目已有节点及接口。修改后检查旧名称、旧层级引用和运行时覆盖。
- 对需要整体保持形状的大区域，在区域根容器使用 `UIAspectRatioConstraint`，内部采用同一套相对坐标。结合可用宽高预算选择约束方式；不要给所有祖先和细碎子项重复约束。
- 进度 Fill、损失条等宽度需要独立变化的对象不套固定宽高比。若小屏可读性或交互尺寸不达标，应调整布局／尺寸预算；比例锁定本身不证明响应式布局合格。
- 图片透明留白、`ScaleType` 和图集裁切会改变实际可见范围。按可见内容和实际槽口校准，不只比较 ImageLabel 的矩形边界。
- 核对根容器是否参与相机避让、随机按钮定位或安全区计算。不能为了布局方便改变这些容器的语义；先读调用点。
- 检查 `ZIndexBehavior`、实际绘制层级与 `ClipsDescendants`。槽内特效应受槽口遮挡；外溢爆点、描边等按设计保留空间，不一律打开或关闭裁切。

## 动态效果与现有事件

- 为实际需要的状态说明触发事件、入场、停留、退场、结束后的业务动作和中断处理。直接使用项目已确认时长，不复制本技能来源项目的数值。用户只给一个口令时长时，先按批准方案或现有字段语义解释；没有其他约定时作为整段总预算并说明分配，不擅自将它作为停留时长再叠加入退场。
- 先读现有事件发送顺序，再绑定表现。比如伤害与动作结束可能在同一调用链发生，采样进度前应确保真实值已刷新；不能无依据地加延迟或新计时器。
- 用户要求“口令退场后开战”时，分别核验口令动画与控制器开始战斗的时刻，不能仅修改淡出效果就声称业务时序已改变。
- QTE 等点击反馈需验证“点击成功—目标受击—数值／进度变化”的关联，沿用已确认伤害和点击规则。不要自行添加伤害文案或奖励表现。
- 使用当前任务必要的 Tween 取消、事件配对和重置逻辑。验证下一次动作、切换状态和退出不会被旧动画回调覆盖，不为理论情况另建状态框架。

## 实机验收与交付

按实际修改选取有意义的检查，不要求每次都跑完整矩阵：

- 对照认可示意图检查大区域比例、间距、字形、文字位置和视觉层级；用运行时 `AbsolutePosition／AbsoluteSize` 定位问题。
- 在目标设备与代表性视口比例检查重叠、裁切、可读性、点击范围和安全区。先读游戏方向设置，不把只支持横屏的项目扩成竖屏改造。
- 进度条检查满值、中间值、接近零及零值；动画检查连续触发、打断、退出与重新进入。不要只查看静止满血截图。
- 区分静态结构检查、注入状态的表现检查和真实交互测试。真实路径中核对口令、点击、伤害、动作结束和退出；模拟显示不能代替实际触发证据。
- 查看资源加载结果和控制台，区分已有问题与本次回归。未验证的平台或不可用资源明确说明，不计作通过。
- 恢复本次测试改变的 Studio 模式与视口，清理自己创建的临时测试产物。不要把测试属性、占位节点或诊断脚本带进正式预制体。
- 按当前阶段交付：预览阶段展示示意图、实现映射与待核实项；实施阶段说明实际修改范围、资源绝对路径及导入对应关系、验收结果和剩余差异。不要只说“已完成”或用检查清单代替证据。

## 可选 Agent team 分工

当素材、脚本和审查可以独立推进时再拆分任务。先分配互不重叠的文件／实例所有权，再约定资源尺寸、槽口坐标、节点名称和动画接口。主代理统一进行 Studio 模式切换与集成验收；子代理未经协调不启动／停止 Play。独立审查只读，不覆盖实现代理的改动。

## 参数来源

时长、字体、风格、素材 ID、输出目录、区域比例和玩法规则全部取自当前任务。PNG 固定口令、原生动态文字、左侧居中进度条、Loss／Settling 等都是可选实现；只有用户选择或当前实现需要时采用。不要默认忽略头像、默认启用团队，或为本技能复制来源项目素材。
